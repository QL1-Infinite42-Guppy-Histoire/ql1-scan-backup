# QL1 Scan Backup — scan.qom.network のクローン／予備サイト

QL1（QOM Layer One）のブロックエクスプローラーを、本家 `scan.qom.network` とは
独立に立ち上げるためのプロジェクト。

## 公開中（2026-11-07）

- **サイト: https://ql1-scan-backup.nepicobsv.workers.dev/**
  （Cloudflare Workers + KV で配信。当初予定の Cloudflare Pages は、直接アップロード
  API がアセット登録で 500 を返し配信できなかったため、同じ Cloudflare アカウントの
  Workers 配信に切り替えた。`worker.js` が KV に置いた `index.html` をそのまま返す。）
- ページ上部に「表示できるのは直近のブロックのみ」の告知を常時表示。
- フッターに Guppy's Guide リンク集へのリンクを掲載。
- **公開範囲の制限（重要）**：QL1の公開RPCは pruned のため、表示できるのは
  直近のブロックのみです。古い履歴は本家 scan.qom.network を使ってください。

## いまあるもの（Phase 1：軽量クローンサイト）

`index.html` 1ファイルだけの静的サイト。サーバーもDBも不要。

- データは QL1 の公開EVM RPC `https://evm-rpc-ql1.mschihuahua.org`
  （Chain ID 766）から**ブラウザが直接**読む。本家scanとは無関係に動く。
- できること：
  - 検索（アドレス / Tx Hash / ブロック番号・Hash）
  - ホーム：最新ブロック一覧、直近Tx（RPCで直近300ブロックを走査）、
    平均ブロック時間、ガス価格
  - ブロック詳細（Tx一覧つき）
  - Tx詳細（成否、ガス、手数料、ログ件数、入力データ）
  - アドレス：QOM残高、Nonce、コントラクト判定、既知トークン
    （ZAP / WQOM / QSWAP）残高
  - アドレスのTx履歴は、本家APIが生きている間だけ補完表示（出典明記）。
    本家が落ちたら履歴は出ないが、残高・ブロック・Tx単体はRPCで見られる
    ＝「予備」として一番効く部分は独立している。
- ヘッダーに RPC と本家API の生死を常時表示するので、
  「本家が落ちたから予備で見る」という切り替えが目で分かる。

### なぜこの方式か（2026-10-30 実測）

- 本家 scan.qom.network は **Blockscout v9.0.2**。
  総ブロック 13,273,366 / 総Tx 2,643,902 / 総アドレス 342,867。
- QL1の公開RPCは **pruned（刈り取り済み）**：古いブロック
  （少なくとも 5,000,000 以下、境界は 5M〜10M の間）は `eth_getBlockByNumber`
  が null を返す。つまり「RPCだけ」では全履歴の完全クローンは作れない。
  完全クローンにはインデックス済みDBが必須（下記 Phase 2）。
- RPCは CORS `*` 許可済み → 静的サイトから直接読める（実測済み）。
- QL1はTxが少ない（実測で当日50件程度）。直近Tx表示はRPC走査で足りる。

## 公開方法（無料・サーバー不要）

`index.html` を置くだけ。どれでも可：

1. **Cloudflare Pages**（推奨：無料、独自ドメイン可、速い）
2. GitHub Pages
3. Netlify / Vercel

独自ドメイン例：`scan-backup.example.com` や `ql1scan.example.com` など、
本家と無関係な自分のドメインを当てる（本家のサブドメインは本家管理者の
権限が要るので、予備としては自分のドメインが正解）。

## Phase 2（完全クローン：本格Blockscout）への道

本家と同等の「全履歴検索・トークン一覧・コントラクト検証表示」まで
再現したい場合：

- Blockscout v9 を Docker で自前運用する
  （バックエンド Elixir + フロント Next.js + PostgreSQL + Redis）。
  目安：4CPU / 16GB RAM〜、ストレージはインデックス分が増え続ける。
  無料枠の小さいサーバーでは現実的でなく、常時稼働のVPSが要る。
- 最大の壁は**過去データ**：公開RPCが pruned のため、過去ブロックを
  後からインデックスできない。選択肢は3つ：
  1. アーカイブノードを持つ人（MT／バリデータ）にRPCを借りる
  2. 本家運営から DB／スナップショットの提供を受ける
  3. 「今日以降」だけを自前インデックスし、過去は割り切る
     （カスタム小型インデクサー＋SQLite/Postgres でも可。本サイトに
     そのDBを読む口を足す形が拡張しやすい）
- つまり Phase 2 は技術より「アーカイブデータの入手」が本体。
  MTへの確認事項に「QL1のアーカイブRPC有無」を足す価値あり。
